# 引导剪枝预编译化：一次离线计算 + 运行时规则树查表

## Context

**现状为什么每次都算**：`ProfileEngine.rankQuestions`（`lib/domain/profile_engine.dart:36-70`）在每次作答后对每题每选项模拟 patch，再对 737 条建议逐条重跑完整 `matchPersona`（≈3.1 万次/次），且引导页 build 路径（header + 每个层页）各算一遍、滑块拖动每帧算一遍 → 主 isolate 冻结，无法完成引导。而 `matchPersona` 里大量判定本是**静态事实**（关键词命中、章节归属、门禁名单），与用户画像无关，却每次重新做字符串拼接 + 全文扫描。

**目标架构（按你的方向）**：
1. 门禁谓词**一次离线编译成 asset 进包**——每条建议 → 结构化判定记录（"规则树"节点：域/前提布尔/关键词命中/章节门禁/名单命中/阶段角色标签）
2. 题序**主干固定**（onboarding.json tier 先粗后细），层内收益序进引导时算一次冻结；低收益跳过保留，用编译谓词微秒级计数
3. 作答 = **查表判定**：737 条 × 纯字段读取（零字符串、零分配，亚毫秒），"已聚焦 X/Y"即时刷新

## 改动清单

### 1. 新增 `lib/domain/gate_traits.dart` —— 单一事实源
- `GateTraits` 不可变记录 + 提取函数 `fromAdvice(Advice, Map<String,Set<int>> ruleSets)`：把 `matchPersona` 中全部静态量一次性提取（prerequisites 类型化、0.6 慢性病关键词命中、0.7 章节门禁、0.8–0.15 门禁名单命中 + 关键词命中、女性健康/阶段标签/特定角色标签/isGeneric）
- `matchPersonaByTraits(traits, profile, …)`：与现行 `matchPersona` 分支、顺序、返回语义**逐字等价**的纯字段判定，签名与现 matchPersona 相同（保持全仓调用方零改动）
- 提取函数仅依赖 Advice 静态字段与 ruleIdSets，不依赖 Flutter——同一份代码供离线生成与运行时兜底编译共用

### 2. 离线生成 asset（`flutter test` 通道，仿 golden 先例）
- 新增 `test/build_gate_traits_test.dart`：带 `GATE_TRAITS_UPDATE=1` 时经真实 `Catalog.load()` 提取全量 traits + sourceHash（对 advice.json+gates.json 规范化内容的 FNV-1a 折叠，不引入新依赖），写入 `assets/data/config/gate_traits.json`（含 schemaVersion/sourceHash/计数）；不带环境变量时校验入库 asset 与随包数据一致
- 数据变更后一条命令重生成；asset 进 git、进包（pubspec 注册）

### 3. 运行时接线（`lib/data/catalog.dart` + `lib/domain/gatekeeper_engine.dart`）
- `Catalog.load()` 读取 gate_traits.json；`GatekeeperEngine` 首用时校验 sourceHash——**不匹配/缺失即用同一提取函数运行时同步编译兜底**（毫秒级，仿 L8 modelVersion 绑定的 fail-safe 模式），`matchPersona` 保持同步签名

### 4. 题序固定 + 查表判定（`lib/domain/profile_engine.dart` + `lib/ui/onboarding/onboarding_view.dart`）
- ProfileEngine：进入引导时用编译谓词算一次层内收益序并冻结；每次作答仅刷新活跃集（737 × 纯字段判定）+ 低收益跳过计数；rankQuestions 不再逐答全量重跑
- OnboardingView：State 缓存 `OnboardingState`，build 路径零引擎调用（header/层页读缓存）；滑块 `onChanged` 只更新数值，`onChangeEnd` 才刷新活跃集

## 等价性保障（三层）
1. **golden 快照零漂移**：`test/golden_test.dart:167` 已固化旧实现对 737 条 × 多组种子画像的 matchPersona 结果，重构后必须原样通过
2. **新增等价性测试**：旧实现保留为 `@visibleForTesting` 参考实现，与编译路径在全 advice × 画像矩阵（空画像/单题作答/种子随机组合）下活跃集逐一比对
3. `test/profile_engine_test.dart` 现有断言（活跃集 == 逐条 matchPersona）继续有效

## 验证
1. `flutter analyze` 清零；`flutter test` 全量通过（含新等价性测试与 golden）
2. `GATE_TRAITS_UPDATE=1 flutter test test/build_gate_traits_test.dart` 生成 asset 并入库
3. `flutter build apk --release` 出 arm64 包 → 真机走完引导：滑块可顺滑拖动、逐题作答无冻结、"已聚焦 X/Y"实时正确

# v1.0.24+25 建议内容与交互匹配

本次将全部 737 条建议绑定到明确的交互配置，其中 56 条建立重点逐条配置。匹配依据是实际任务：查阅规则、情境核对、行动核对、每日习惯、办事步骤、材料核对、数值记录、日期计划、书面计划、成本比较、紧急求助。没有将交互动画的多少作为适配程度的判断依据。

## 内容与交互审查结论

原分配不能认为最佳，存在可复现的类型错配与共用组件问题：

- 家暴、住院账单、创业贷款、导盲犬权益被分配通用强度滑块，输入与任务无关。
- 酒驾禁忌显示基于杯数的“代谢完毕”时间，可能被误读为可以驾驶。现已移除推算，保留规则查阅。关于个体酒精代谢差异，参考 [HSE 酒精与驾驶说明](https://www2.hse.ie/living-well/alcohol/health/how-alcohol-can-affect-everyday-life/drinking-and-driving/)。
- 22 条窗口卡统一从查看时开始显示 14 天，不能对应购买冷静期、退货、车辆质量、个人截止日期等不同情境。
- 紧急建议卡复用演示热线和“立即止付、保存证据、处理完毕”，与多数急救内容不相干。全局紧急入口原本已有真实拨号，两处实现不一致。
- 血压输入预置读数，并使用有限范围滑杆，可能将示例保存为真实测量。
- 安全带图把前排预锁，仅检查后排却宣称四座锁止。
- 材料清单截断到四项，并把说明性语句当凭证；办事与决策卡直接将条件、限制与动作统一作为勾选项。
- 规则盖章宣称进入长期记忆，情境卡全勾后宣称“拦截解除”；这些反馈不能由点击行为证明。
- 部分标题没有具体指标，而实际目标只在首个原子动作里；卡片原先没有总是展示这一目标。

内容仍需以“适用条件、实际行动、限制、材料、日期、指标”分层维护。此次保留原始建议、证据包和门禁语义，重点修正可确认的交互错配与状态反馈；没有宣称完成所有医疗、法律证据的最新逐条复核，也没有以可用性实验认证“最佳”。

## 实施与数据源

新增作者配置 `app/data-src/interaction_overrides.json`。流水线 `steps/interactions.dart` 为全量生成 `styles/display_bindings.json`，每行包含实际 style、可选专用 renderer、items、notes 和 completion 合约。对原有 source style 和 cron 不做替换，因此默认触发计划不随 UI 匹配漂移。

实际组件优先使用绑定 style；生活指南的交互筛选和数量也使用相同口径。原始 actType 保留给旧触发推断和回归快照，避免循环依赖“调度决定交互、交互反过来决定调度”。

- 数值记录：血压、遛狗时长、周累计活动。输入为空，验证后保存带时间的实际数据，最多保留最近100条；不自动给出医学诊断。
- 日期计划：用户明确设置截止日期；冷静期和退货截止日分开确认，不推定法律期限，不因浏览启动倒计时，不自动开启通知。
- 书面计划：时间、地点或情境、具体行动需要真实填写。
- 紧急卡：显示情境指引及匹配原文的系统拨号入口，可进入全局紧急求助；不将点按钮标记为已脱险。
- 材料清单：使用逐项材料名称，不再截断到四项，不声称已经上传附件。
- 规则与情境核对：只保存阅读或核对标记，不显示100%完成或风险解除。
- 安全带：没有预确认座位，核对本人及同乘人员的实际情况。
- 成本比较：标明初始值是示例，结果仅供比较，不直接宣称外包一定划算。

记录、日期、书面计划与阅读标记使用独立本地存储；不随日/周打卡换期清空。升级时迁移旧的非行动完成度，避免旧版盖章或示例读数继续表现为已完成。完成后的短时排序定时器也会在状态对象销毁时取消。

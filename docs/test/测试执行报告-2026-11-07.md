## 本次发现并修复的问题（应用代码缺陷 · 6 处）

### 第一轮（主 E2E 暴露）

1. **当下页 320px 窄屏横向溢出 8.3px**（`lib/ui/now/now_view.dart`）：
   「1.5小时核心行动」标题为 Row 中不可折行的裸 Text。修复：`Expanded` + 省略号。
2. **带背景色容器内直接嵌 ListTile/CheckboxListTile**（框架断言，debug 报错浮层）：
   `emergency_sheet`（实测 ×9）、`me_view`（实测 ×4）、`decision_tree_sheet`（同型隐患）。
   修复：统一以 `Material(type: MaterialType.transparency)` 承载墨水涟漪。

### 第二轮（时钟协同与通知验证暴露，均为用户可感知的功能性缺陷）

3. **自建待办的时点提醒永不触发**（`lib/domain/reminder_engine.dart`）：
   合成待办建议（FNV 稳定 id ≥10000）不在 `catalog.byId`，到点后按 id 反查得
   null 被静默跳过。修复：`_RegisteredReminder` 注册时直接持有 Advice 引用。
4. **新建待办/改触发/换画像后提醒漏注册**（`lib/state/app_store.dart`）：
   `syncReminderRegistry` 在 `notifyListeners` 之前读取今日流缓存（旧流），
   新待办要等下一次状态变更才注册（实测 registered=29 < todayLen=30）。
   修复：sync 前先失效缓存（一处修复同时治好 addUserTodoItem /
   setTriggerConfig / updateProfile 等全部调用路径）。
5. **系统通知通道从未初始化成功——主动探查通知在现网从未发出过**
   （`lib/infra/notifications/mobile_notification_service.dart`）：
   `AndroidInitializationSettings('ic_launcher')` 指向 mipmap 资源，
   插件要求 drawable → `initialize` 抛 `invalid_icon` 被静默吞掉
   （实测 PlatformException 全文）。修复：新增白色阶梯剪影
   `drawable/ic_notification.xml` + 引用改名；catch 增加留痕防止再次静默。
6. `init` 链路补日志：`plugin.initialize` / `requestNotificationsPermission`
   返回值 debug 留痕。

### 测试基线设施

- `android/app/build.gradle.kts`：release 仍仅 arm64-v8a（生产行为不变）；
  debug 追加 x86_64 以便模拟器 E2E；release 支持 `-Pabi-extra=x86_64` 出本地验证包。
- 新增 5 个 E2E 文件：主套件 / 时钟协同 / 盾牌+父母适用 / 提醒对话框 / 探查通知。
- 实机稳定性模式（沉淀在 E2E 代码注释）：懒加载列表用视口中心拖拽滚动；
  tap 前滚入屏幕中部安全带；Tab 定位限定 NavigationBar；弹层字段限定弹层作用域；
  业务断言以 store 状态为权威；时钟协同用「测试内轮询等待宿主改时钟」。
- 工具链注意事项：`flutter test` 每轮重装并清数据（单进程多阶段方案）；
  运行前 `adb logcat -c`（时钟跳转会让工具抓到陈旧 VM Service 行导致
  WebSocket 握手失败）；模拟器长跑后可能 OOM 崩溃（宿主需清理 gradle daemon）。
